# Сценарии использования (Use case)

**Акторы:**

| Актор | Тип | Роль в сценариях |
|---|---|---|
| Соискатель | основной | Регистрируется, ведёт резюме, ищет вакансии, откликается |
| Работодатель | основной | Публикует вакансии, обрабатывает отклики |
| Администратор | основной | Модерирует вакансии |
| Система | вспомогательный | Проверяет данные, отправляет письма и уведомления, ведёт статусы |


## Диаграмма вариантов использования

![Диаграмма вариантов использования](../diagrams/use-case-diagram.png)

Соискатель использует 1 — 5, работодатель — 1, 2, 6 и 8, администратор — 7. «Система» участвует во всех сценариях как вспомогательный актор.


### 1. Регистрация нового пользователя

| Поле | Значение |
|---|---|
| Актор | Соискатель или работодатель (незарегистрированный); вспомогательный — Система |
| Цель | Получить активную учётную запись в выбранной роли |
| Предусловия | Адрес электронной почты доступен актору; такой адрес в системе ещё не зарегистрирован |
| Триггер | Актор нажимает «Регистрация» |
| Гарантии успеха | Учётная запись активирована, роль зафиксирована, актор может войти |
| Описание | 1. Актор открывает форму регистрации.<br>2. Актор выбирает роль: соискатель или работодатель.<br>3. Актор вводит адрес электронной почты и пароль.<br>4. Система проверяет формат данных, уникальность адреса и соответствие пароля политике.<br>5. Система создаёт неактивную учётную запись и отправляет письмо со ссылкой подтверждения.<br>6. Актор переходит по ссылке из письма.<br>7. Система активирует учётную запись и предлагает войти. |
| Расширение | • Адрес уже зарегистрирован: система сообщает об этом; возврат к шагу 3 или переход к UC-02.<br>• Пароль не соответствует политике: система показывает нарушенное правило; возврат к шагу 3.<br>• Письмо не пришло или ссылка устарела: актор запрашивает повторную отправку; возврат к шагу 5. |


### 2. Вход в систему

| Поле | Значение |
|---|---|
| Актор | Соискатель, работодатель, администратор; вспомогательный — Система |
| Цель | Получить доступ к функциям своей роли |
| Предусловия | Учётная запись активирована (UC-01) и не заблокирована |
| Триггер | Актор открывает страницу входа или пробует открыть закрытую страницу |
| Постусловия | Сессия создана, актор на главной странице с лентой вакансий |
| Описание | 1. Актор открывает страницу входа.<br>2. Актор вводит адрес электронной почты и пароль.<br>3. Система проверяет учётные данные.<br>4. Система создаёт сессию.<br>5. Система открывает главную страницу с вакансиями и навигацией: поиск, избранное, личный кабинет, выход. |
| Расширение | • Данные неверны: система показывает общую ошибку, не указывая неверное поле; возврат к шагу 2. После серии неудач вход временно блокируется.<br>• Учётная запись не активирована: система предлагает повторно отправить письмо подтверждения (UC-01, шаг 5).<br>• Актор забыл пароль: система отправляет одноразовую ссылку сброса на почту, актор задаёт новый пароль и возвращается к шагу 2.<br>• Актор не авторизован и открыл закрытую страницу: система перенаправляет на страницу входа |


### 3. Создание и публикация резюме

| Поле | Значение |
|---|---|
| Актор | Соискатель; вспомогательный — Система |
| Цель | Иметь заполненное резюме, с которым можно откликаться на вакансии |
| Предусловия | Соискатель авторизован (UC-02) |
| Триггер | Соискатель выбирает «Создать резюме» в личном кабинете или при отклике без резюме (UC-05, шаг 3a) |
| Постусловия | Резюме сохранено и доступно для откликов; дата последнего обновления зафиксирована |
| Описание | 1. Соискатель открывает раздел «Резюме» в личном кабинете.<br>2. Соискатель заполняет контактные данные, желаемую должность и зарплатные ожидания.<br>3. Соискатель добавляет опыт работы, образование, навыки и блок «О себе».<br>4. Система показывает индикатор заполненности и список незаполненных разделов.<br>5. Соискатель сохраняет резюме.<br>6. Система проверяет обязательные поля (желаемая должность, контакт, опыт или признак «без опыта»).<br>7. Система фиксирует дату обновления и показывает резюме в кабинете. |
| Расширение | • Соискатель прерывает заполнение: система сохраняет черновик; соискатель продолжает позже с шага 2.<br>• Соискатель скрывает резюме от работодателей<br>• Обязательные поля не заполнены: система не сохраняет резюме для публикации и указывает поля; возврат к шагу 2.<br>• Соискатель добавляет, меняет или удаляет несколько записей опыта и образования. |


### 4. Поиск и просмотр вакансий

| Поле | Значение |
|---|---|
| Актор | Соискатель; вспомогательный — Система |
| Цель | Найти подходящую вакансию и ознакомиться с её описанием |
| Предусловия | Соискатель авторизован (UC-02); в системе есть опубликованные вакансии |
| Триггер | Соискатель на главной странице вводит запрос или открывает фильтры |
| Постусловия | Соискатель находится в карточке вакансии и может откликнуться или добавить вакансию в избранное |
| Описание | 1. Система показывает ленту опубликованных вакансий.<br>2. Соискатель вводит поисковый запрос по ключевым словам.<br>3. Соискатель применяет фильтры: регион, доход, опыт, тип занятости, график.<br>4. Система пересчитывает результат и показывает число найденных вакансий.<br>5. Соискатель выбирает сортировку: релевантность, дата или зарплата.<br>6. Соискатель открывает карточку вакансии.<br>7. Система показывает полное описание, данные работодателя и действия «Откликнуться» и «В избранное». |
| Расширение | • Ничего не найдено: система показывает сообщение и рекомендации, соискатель сбрасывает фильтры одним действием и возвращается к шагу 2.<br>• Соискатель добавляет вакансию в избранное и возвращается к результатам; позиция в списке сохраняется.<br>• Соискатель выбирает «Откликнуться» — переход к UC-05.<br>• Соискатель сохраняет поисковый запрос или жалуется на вакансию.<br>• Вакансия снята с публикации пока соискатель был в карточке: система не принимает отклик (UC-05, шаг 3.2). |


### 5. Отклик на вакансию

| Поле | Значение |
|---|---|
| Актор | Соискатель; вспомогательный — Система; получатель — работодатель |
| Цель | Передать работодателю своё резюме на опубликованную вакансию |
| Предусловия | Соискатель авторизован; вакансия опубликована; отклика на неё ещё нет |
| Триггер | Соискатель нажимает «Откликнуться» в ленте, результатах поиска или карточке |
| Постусловия | Отклик создан со статусом «Отправлен», работодатель уведомлён |
| Описание | 1. Соискатель выбирает «Откликнуться».<br>2. Система проверяет, что вакансия опубликована и отклика на неё нет.<br>3. Система проверяет наличие заполненного резюме.<br>4. Соискатель выбирает резюме и при желании пишет сопроводительное письмо.<br>5. Соискатель подтверждает отправку.<br>6. Система создаёт отклик со статусом «Отправлен» и записывает его в историю.<br>7. Система уведомляет работодателя о новом отклике.<br>8. Система показывает соискателю отклик в личном кабинете. |
| Расширение | • 2.1 Отклик уже отправлен: система показывает его текущий статус и не создаёт новый.<br>• Вакансия снята с публикации или закрыта: система отказывает и сообщает об этом, сценарий завершён.<br>• 3.1 Резюме нет: система предлагает его создать (UC-03) и после сохранения возвращает к шагу 3. У соискателя несколько резюме: он выбирает одно из них.<br>• Соискатель отменяет отправку: отклик не создаётся, возврат к карточке вакансии.<br>• Соискатель отзывает отклик, пока работодатель не рассмотрел его.<br>• Работодатель не меняет статус за 7 дней: система маркирует отклик «без ответа» и уведомляет соискателя. |


### 6. Публикация вакансии

| Поле | Значение |
|---|---|
| Актор | Работодатель; вспомогательный — Система |
| Цель | Разместить вакансию так, чтобы её увидели соискатели |
| Предусловия | Работодатель авторизован; профиль компании заполнен |
| Триггер | Работодатель выбирает «Создать вакансию» |
| Постусловия | Вакансия передана на модерацию (UC-07) |
| Описание | 1. Работодатель открывает форму создания вакансии.<br>2. Работодатель заполняет название, описание, требования, условия, регион, тип занятости и по желанию зарплату.<br>3. Работодатель отправляет вакансию на модерацию.<br>4. Система проверяет обязательные поля.<br>5. Система переводит вакансию в статус «На модерации» и создаёт задачу администратору.<br>6. После решения модератора (UC-07) система уведомляет работодателя о результате. |
| Расширение | • Работодатель прерывает заполнение: черновик сохраняется, публикация не происходит.<br>• Обязательные поля не заполнены: система не принимает вакансию и указывает поля; возврат к шагу 2.<br>• Вакансия отклонена: работодатель видит причину, исправляет вакансию и возвращается к шагу 3.<br>• Вакансия одобрена: система публикует её в ленте, работодатель может редактировать, приостанавливать и архивировать её. |


### 7. Модерация вакансии

| Поле | Значение |
|---|---|
| Актор | Администратор; вспомогательный — Система |
| Цель | Не пустить в ленту вакансии, нарушающие правила платформы |
| Предусловия | Администратор авторизован; в очереди есть вакансия со статусом «На модерации» |
| Триггер | В очереди появилась новая вакансия или администратор открывает очередь |
| Постусловия | Вакансия опубликована или возвращена работодателю с причиной; решение записано в журнал |
| Описание | 1. Администратор открывает очередь модерации и выбирает вакансию.<br>2. Администратор проверяет содержание вакансии.<br>3. Администратор одобряет вакансию.<br>4. Система публикует вакансию и уведомляет работодателя.<br>5. Система записывает действие в журнал администратора. |
| Расширение | • Вакансия нарушает правила: администратор отклоняет её и обязательно указывает причину; система возвращает вакансию работодателю.<br>• Администратор отклоняет без причины: система не принимает решение и требует указать причину.<br>• Вакансия уже обработана другим администратором: система показывает текущий статус без повторного решения |


### 8. Обработка отклика работодателем

| Поле | Значение |
|---|---|
| Актор | Работодатель; вспомогательный — Система; получатель — соискатель |
| Цель | Рассмотреть отклик и сообщить соискателю решение |
| Предусловия | Работодатель авторизован; на его вакансию есть отклик со статусом «Отправлен» (UC-05) |
| Триггер | Уведомление о новом отклике или переход в список откликов |
| Постусловия | Статус отклика изменён, соискатель уведомлён, история статусов сохранена |
| Описание | 1. Работодатель открывает список откликов по вакансии и при необходимости фильтрует его по статусу.<br>2. Работодатель открывает отклик и резюме кандидата.<br>3. Система фиксирует статус «Просмотрен» и уведомляет соискателя.<br>4. Работодатель выбирает статус из справочника: приглашение, отказ, в резерве.<br>5. Система сохраняет новый статус в истории и уведомляет соискателя.<br>6. Соискатель видит новый статус в личном кабинете. |
| Расширение | • Приглашение на собеседование: работодатель указывает дату, время и формат встречи, далее шаг 5.<br>• Отказ: работодатель может приложить комментарий из шаблона или свободный текст.<br>• Нужно обсудить детали: работодатель и соискатель обмениваются сообщениями в чате отклика.<br>• Кандидат подходит, но отказаться не нужно: работодатель сохраняет резюме в резерв.<br>• Работодатель не меняет статус за 7 дней (допущение): система маркирует отклик «без ответа» и уведомляет соискателя. |
