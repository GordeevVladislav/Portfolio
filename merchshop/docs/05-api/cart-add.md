# 5. API: добавление товара в корзину

`POST /api/v1/cart/add`

Добавляет товар в корзину и резервирует его на 15 минут. Полная спецификация: [openapi.yaml](openapi.yaml).

## Изменения относительно исходного решения

| Было | Стало | Причина |
|------|-------|---------|
| `user_id` в теле запроса | Пользователь определяется по токену `Authorization: Bearer` | Иначе можно подменить id и изменить чужую корзину. Ошибка «пользователь не найден» заменена на `401` |
| `400` для «нет в наличии» | `409 Conflict` с кодами `OUT_OF_STOCK`, `INSUFFICIENT_STOCK`, `RESERVED_BY_OTHER` | Это конфликт состояния, а не неверный запрос. Клиенту нужно различать причины |
| Только текст ошибки | Машиночитаемое поле `code` + `message` | Текст меняется, код стабилен |
| Нет валидации | `422` для неверного `quantity` | `quantity` должно быть целым от 1 до 10 |
| Нет информации о подарке | В ответе `gift` и `gift_remaining_amount` | Фронтенду нужно показать «до подарка осталось N ₽» |
| `cart_total` = 1 (непонятно, что это) | `cart.items_count` и `cart.subtotal` | Неоднозначное поле |

## Запрос

Заголовки: `Authorization: Bearer <token>`, `Content-Type: application/json`.

```json
{
  "product_id": 456,
  "quantity": 1
}
```

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| product_id | integer | да | Идентификатор товара. Наклейки (товар-подарок) добавить вручную нельзя |
| quantity | integer | да | Количество, от 1 до 10 |

## Успешный ответ: 200 OK

```json
{
  "status": "success",
  "message": "Товар добавлен в корзину",
  "item": {
    "product_id": 456,
    "quantity": 1,
    "unit_price": 1500.00,
    "reserved_until": "2026-05-25T14:45:00Z"
  },
  "cart": {
    "items_count": 1,
    "subtotal": 1500.00
  },
  "gift": {
    "applied": false,
    "threshold": 2000.00,
    "remaining_amount": 500.00
  }
}
```

Повторное добавление того же товара увеличивает количество и устанавливает новое время брони для всей позиции (допущение, подтвердить у заказчика).

## Ошибки

Единый формат:

```json
{
  "status": "error",
  "code": "OUT_OF_STOCK",
  "message": "Товара нет в наличии"
}
```

| HTTP | code | Когда | Дополнительные поля |
|------|------|-------|---------------------|
| 401 | UNAUTHORIZED | Нет или неверный токен | |
| 404 | PRODUCT_NOT_FOUND | Товара с таким id нет | |
| 409 | OUT_OF_STOCK | Физический остаток равен нулю | |
| 409 | INSUFFICIENT_STOCK | Доступно меньше запрошенного | `available` |
| 409 | RESERVED_BY_OTHER | Товар есть, но полностью забронирован другими | `available_at` (время ближайшего освобождения) |
| 422 | VALIDATION_ERROR | Неверные поля тела запроса | `errors[]` |

Пример `RESERVED_BY_OTHER`:

```json
{
  "status": "error",
  "code": "RESERVED_BY_OTHER",
  "message": "Товар зарезервирован другим покупателем",
  "available_at": "2026-05-25T14:40:00Z"
}
```

## Гарантии

- Резервирование атомарно: при конкуренции за последнюю единицу ровно один запрос получает `200`, остальные `409`.
- Метод не идемпотентен по определению (повторный вызов увеличивает количество). Для защиты от двойного клика клиент может передавать заголовок `Idempotency-Key`, сервер хранит результат 10 минут.
